This page describes a basic `config.json` file. This file configures your
action, and it sets the events that start the action.

### An example of config.json

```json
{
  "slug": "discord",
  "name": "Discord",
  "triggers": [
    {
      "type": "on_create",
      "entities": [ "IssueComment", "LinkedIssue" ]
    },
    {
      "type": "source_webhook",
      "entities": [ "discord" ]
    }
  ],
  "integrations": [ "discord" ]
}
```


## The `config.json` file

The `config.json` file configures an action in Vantik. Each action has its own
set of properties. These properties give the behaviour of the action, the events
that start it, and the integrations that it uses. The fields are below.

### The fields

#### `slug`
- **Type:** `string`
- **Description:** the unique identifier of the action. Vantik uses this value
  internally to start the correct action.
- **Example:** `"slug": "discord"`

#### `name`
- **Type:** `string`
- **Description:** the name of the action for a reader. Vantik shows this name
  where the action makes a change, for example on a new issue or on a new
  comment.
- **Example:** `"name": "Discord"`

### `triggers`

The `triggers` field gives the conditions that start the action. It is a list of
objects. Each object gives one type of trigger and the entities for that
trigger.

#### `type`
- **Type:** `string`
- **Description:** the type of trigger that starts the action. These are the
  types:
  - `on_create`: Vantik starts the action when a person makes an entity.
  - `on_update`: Vantik starts the action when a person changes an entity.
  - `on_delete`: Vantik starts the action when a person deletes an entity.
  - `source_webhook`: an external event starts the action. That event usually
    comes from an integration such as Discord or GitHub.
- **Example:**
  ```json
  {
    "type": "on_create"
  }
  ```

#### `entities`
- **Type:** an array of strings
- **Description:** the entities for the trigger. An entity is an object or a
  record in Vantik, such as an issue or a comment. These entities are common:
  - `Issue`: an issue in the project management system.
  - `IssueComment`: a comment on an issue.
  - `LinkedIssue`: a URL that a person links to an issue.

  With the `source_webhook` type, each entity is an integration.

### `integrations`

The `integrations` field lists the external systems of the action. The action
needs access to each of these systems to do its work.

- **Type:** an array of strings
- **Description:** the integrations that the action uses. For example, an
  action that sends an update to Discord lists `discord` here.
- **Example:**
  ```json
  {
    "integrations": [ "discord" ]
  }
  ```
