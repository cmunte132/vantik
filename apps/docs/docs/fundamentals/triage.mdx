## Overview

Triage is a workflow category for new issues that no person has read yet. Each
team has a status in this category. A new team gets the status **Triage**. A
support team gets the status **New**.

Triage is not a separate inbox. An issue in triage is an ordinary issue of the
team. The list and the board show it in a status group, with the other issues.

![The Triage group in the list of a team, with three new
issues](/img/docs/triage/triage-group.png)

The list shows the Triage group after the Backlog group. The Kanban board shows
the Triage column first.

## How an issue gets into triage

- **Email.** The [Email](/integrations/email) integration makes each new email
  an issue in the triage status of the mapped team.
- **A template.** An issue template can set the triage status. An issue that
  you create from that template then starts in triage.
- **The knowledge bank.** The **Knowledge gardener** bot opens issues with the
  `knowledge` label, for example for a gap in the knowledge of the workspace.
  Such an issue starts in triage. If the team has no triage status, it starts
  in the backlog.
- **By hand.** You can set the triage status on any issue.

The new issue dialog starts an issue in **Backlog**, not in triage. An agent
that uses the MCP server also creates an issue in the backlog,
unless it names a different status. The
GitHub integration does not make a Vantik issue from a new GitHub issue.

## What Vantik does with an issue in triage

When an issue is in the triage status, Vantik gives help to the person who
reads it:

- **Similar issues.** When you open the issue, Vantik finds issues with a
  similar text. The issue page then shows them in a **Similar Issues** panel.
  Click an issue in the panel to open it. If the issue is a duplicate, open the
  menu of the issue and select **Duplicate of...**.
- **Suggested modules.** If the issue has no modules, Vantik can suggest
  modules. They show under **Modules** at the right of the issue page. Read
  [The issue page](/fundamentals/issues#the-issue-page).

The module suggestions need an AI endpoint. The similar issues do not. If your
instance has no embedding model, Vantik searches with the title of the issue.
When the issue leaves triage, Vantik removes the module suggestions that
remain.

## How to triage an issue

There is no accept or decline control. To triage an issue, do these steps:

1. Open the issue and read it.
2. Look at the **Similar Issues** panel. If the issue is a duplicate, mark it
   as a duplicate.
3. Set the properties: priority, labels, assignee and modules.
4. Change the status. Use **Backlog** or **Todo** for work that the team
   accepts. Use **Canceled** for work that the team does not do.

To see only the issues in triage, filter the list by **Status**, and select the
triage status. You can save this filter as a view. Read
[Views](/fundamentals/views).

## Triage cannot be turned off

The workflow of each team includes the triage category. You can rename the
triage status in the **Workflow** settings of the team, but you cannot remove
it. If no issue is in triage, the list does not show the Triage group. The
group shows again if you turn on **Show empty groups** in **Display
options**.
