## Overview

The GitHub integration keeps your development process in step with Vantik:

- **Link a pull request.** Link a pull request to the related Vantik issue.
  When a person closes the pull request, the linked Vantik issue moves to
  "Done".
- **Make an issue automatically.** A new GitHub issue makes a Vantik issue in
  triage.
- **Keep both sides in step.** A change on one platform goes to the other
  platform: the closure of an issue, a comment, and the other updates.

:::note
The GitHub integration is an [Action](/docs/actions/overview). Therefore you
must configure trigger.dev first. See
[background jobs](/docs/oss/self-deployment#background-jobs-triggerdev).
:::

## How to configure the integration

### Connect GitHub

1. Open **Settings → Overview → Integrations → GitHub**.
2. Give Vantik access to your GitHub account.
3. Select the GitHub organisation for the connection.
4. Select all the repositories, or select the repositories that you want.

### Configure the action

1. Open **Settings → Overview → Actions → GitHub → Configuration**.
2. Give the repository, the Vantik team, and the label. That label makes a
   GitHub issue from a Vantik issue.

Notes:

- Each Vantik team can link to one GitHub repository only.
- One label starts the action for all the linked repositories and all the
  linked teams.
