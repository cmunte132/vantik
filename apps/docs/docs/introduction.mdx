Vantik is an issue tracker for people and for agents. You host it yourself, and
you can change it, because it is open source.

![The issue page of Vantik. The issue has a description, a Definition of Done
with three criteria, sub-issues, comments, and a Delegate to an agent
button.](/img/docs/issues/issue.png)

## What Vantik does

- **Issues.** Teams track work as issues, with states, labels, cycles, projects
  and views. Each issue can have a Definition of Done: a list of criteria that
  the work must meet. Read [Issues](/fundamentals/issues).
- **Agents.** An agent is a member of the workspace that does work. You connect
  your own agent, for example a coding assistant, through the MCP server. Read
  [How to connect an MCP client](/api-reference/connect-mcp).
- **Agent runs.** On an issue, a person can delegate the work to an agent. The
  agent then works on the issue in the background, in an agent run. When the
  run ends, the agent posts a comment on the issue that tells what it did. The
  issue shows this comment as the card of the run. If the run opened a pull
  request, Vantik links the pull request to the issue. Read
  [Delegate an issue to an agent](/agents/delegating-an-issue).
- **The knowledge bank.** Pages hold what the workspace knows about its own
  software. People read and write pages. Agents read pages and add facts to
  them. Read [Knowledge](/fundamentals/knowledge).
- **The product axis.** A product is a thing that you ship. A module is where
  the code is, usually one repository. A capability is what the software does.
  An issue can name the modules and the capability that it changes. Read
  [Concepts](/concepts#products-modules-and-capabilities).

## Integrations

An integration connects Vantik to a tool that you use. Vantik has these
integrations:

- **GitHub**: a new issue in a team that maps to a repository also opens in
  GitHub. On an issue that syncs with a GitHub issue, comments go in both
  directions. A pull request links to the issue that its branch name or its
  commit messages name.
- **Git hosts**: a Forgejo, Gitea or GitLab host, or any git host that serves
  HTTP or HTTPS.
- **Local repositories**: a git repository on the disk of the server machine.
- **Discord**: a message in a Discord channel that is linked to an issue
  becomes a comment on that issue.
- **Email**: an email becomes an issue, with its attachments.
- **Bug Enricher**: posts a suggested resolution on each new issue with the
  `bug` label. The model of the server writes it.

Read [Integrations](/integrations/overview).
