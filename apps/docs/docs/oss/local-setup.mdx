## Overview

For development, run only the service containers: PostgreSQL and Redis.
Run the server and the webapp on your host, with hot reload.
These containers publish their ports on localhost for this purpose.

You need these tools:

- Node.js 22.12 or later. Vite also accepts Node.js 20.19 or a later 20
  release: its range is `^20.19.0 || >=22.12.0`. The CI workflow uses Node.js 22.
- pnpm 10. To install it, run `npm i -g pnpm@10`.
- Docker, or Podman with the compose provider

## Steps

1. Clone the repository and make your `.env` file. The default values work for
   local development. The one exception is the key that encrypts the
   credentials of agent runs, which has no default, and the second command
   makes it.

```bash
git clone https://github.com/cmunte132/vantik.git
cd vantik
cp .env.example .env
echo "CREDENTIAL_ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
```

2. Start the service containers only. This command starts no webapp and no
   server.

```bash
docker compose up -d postgres redis
```

3. Install the dependencies and apply the database schema.

```bash
pnpm install
pnpm migrate
```

4. Run the server on port 3001 and the webapp on port 3000, with hot reload.

```bash
pnpm dev
```

:::tip
If the full stack already runs in containers, the app ports are in use. To free
them, run `docker compose stop webapp server`.
:::

5. **Open the application.** Go to
   [http://localhost:3000](http://localhost:3000). The login screen appears.
   Type your email address.

![The sign-in page, with an email address typed in](/img/docs/getting-started/sign-in.png)

6. **Get the login code or the magic link.** In development, the server
   writes both values to its log:

```text
Enter this login code in the app:
123456

Or click here to log in with this magic link:
http://localhost:3000/auth/verify?preAuthSessionId=example#example
```

   Enter the code in the application, or open the link in your browser.

:::tip
A passkey replaces step 5 and step 6. Select **Create an account with a
passkey**. Then authenticate with Touch ID, Windows Hello, or a security key.
The server sends no email, and you read no log. WebAuthn treats `localhost` as a
secure context, so this method works without TLS. See
[How to sign in](/oss/self-deployment#how-to-sign-in).
:::

7. Give your details, and set up your account and your workspace.

![The onboarding form for a new account and its workspace](/img/docs/getting-started/onboarding.png)

8. **Create your first issue.** Press `C` anywhere in the workspace. Once your
   team has issues, **My issues** shows the ones assigned to you:

![My issues in a workspace with a few issues](/img/docs/issues/my-issues.png)


## Search

The Compose database image includes pgvector. The migrations enable FTS, pg_trgm, and pgvector.
PostgreSQL triggers update searchable text in the same transaction as each document change.
Search works without an external service.

Set `EMBEDDINGS_SOURCE=local` in `.env` for semantic search with the local CPU model.
Leave it unset for keyword search only. See [Search](/oss/self-deployment#search)
for the model defaults, hosted endpoints, and offline use.
