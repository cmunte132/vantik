## Overview

Vantik is an issue tracker for developers and for agents. You host it yourself,
because there is no cloud service. The Docker Compose stack in the main
repository needs no other setup. It starts the webapp, the API server, and all
the services: PostgreSQL and Redis. PostgreSQL also provides search.
The default values work, except for one secret, which the second command makes.

## How to run it

You need Docker, or Podman with the compose provider.

```bash
git clone https://github.com/cmunte132/vantik.git
cd vantik
cp .env.example .env
echo "CREDENTIAL_ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
docker compose up -d
```

Open [http://localhost:3000](http://localhost:3000). Then sign in with any email
address. If you configure no SMTP server, the server writes the magic login link
to its log and sends no email:

```bash
docker compose logs server | grep -A5 "magic link"
```

There is a second method, and it needs no log. Select **Create an account with a
passkey**. Then authenticate with Touch ID, Windows Hello, or a security key.
The server sends no email, so you need no mail server. See
[How to sign in](/oss/self-deployment#how-to-sign-in).

Search works without an external service. Set `EMBEDDINGS_SOURCE=local` in `.env`
to add semantic search with a local CPU model. Leave it unset for keyword search only.
See [Search](/oss/self-deployment#search) for hosted models and offline use.

## Optional compose profiles

Some services are in a compose profile. `docker compose up -d` does not start
them. A service in a profile starts only when you name its profile:

- `sandbox` starts the sandbox host. Hosted agent runs work in the microVMs that
  the sandbox host starts. This container needs `/dev/kvm`, so it is for Linux
  hosts. On macOS, run the sandbox host natively. Read
  [Hosted agent runs](https://github.com/cmunte132/vantik#hosted-agent-runs) in
  the README for the two methods.
- `s3` starts MinIO and `minio-bucket`, which makes the bucket. MinIO is an
  object store that uses the S3 protocol. Use it to try the S3 backend for file
  attachments. Read
  [File attachments](/oss/self-deployment#file-attachments).

To start the services of a profile, add the profile name to the command:

```bash
docker compose --profile s3 up -d minio minio-bucket
```
